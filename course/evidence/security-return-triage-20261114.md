# 타인 주문 접근 거부와 반품 결함 · 보안 신호 정답 초안

상태: **단건 실측 완료 / AI 판정·PR·배포 미검증** · 2026-11-14

## 관측 사실

- 가짜 회원 Bob이 Alice 주문 9001의 **상세 조회**를 시도했을 때 레드·그린 모두 HTTP 200 / 본문 code 500으로 거부됐고 `access.denied.not_owner` 이벤트가 기록됐다.
- 같은 Bob이 Alice 주문 9002에 **반품 신청**을 했을 때, 레드에서는 HTTP 200 / 본문 code 200으로 잘못 허용됐다. `measurements/stages-red-20261114T003106Z.json`의 `security_foreign_return`이 근거다. 레드가 만든 가짜 반품 행은 실행 표식으로 정리했다.
- 그린에서는 같은 종류의 반품 신청이 HTTP 200 / 본문 code 500으로 거부됐고, Loki에서 `access.denied.not_owner`를 확인했다. `measurements/stages-green-20261114T003602Z.json`과 `measurements/log-evidence-20261114.json`이 근거다.

## 판단과 반증

**신호:** 타인 주문 접근 거부는 추가로 조사할 이유가 된다. 이 한 줄만으로 침해 성공이나 반품 API 결함은 확정되지 않는다.

**별도 시험으로 확인한 결함:** 레드 상태의 타인 반품 신청이 실제로 허용됐다. 조회 API의 소유권 검사가 반품 신청에도 적용된다고 가정하면 놓치는 문제다.

**남은 검증:** 본인 반품이 보호 기능을 켠 뒤에도 유지되는 회귀 시험, 반복 재현, PR·CI·배포 뒤 재시험은 아직 필요하다. HTTP 바깥 상태가 200인 거부를 403/404 통계로 계산하면 안 된다.

## 에이전트가 멈출 곳

에이전트는 원문과 반증을 정리하고 “반품 API의 소유권 확인 시험”을 제안할 수 있다. 사람이 시험으로 결함을 확인하고 수정 요청을 승인하기 전에는 차단·코드 수정·머지를 하지 않는다.
