# 가격 없는 주문 500 · 근거 지도와 RCA 정답 초안

이 사건을 재현하다 발견한 별개 환경·측정 문제와 반품 사건의 원인 설명은 [랩 RCA 계속 기록](../../rca-20261114.md)에 모은다. 아래는 **가격 없는 주문 한 건**의 근거 지도다.

상태: **단건 실측과 코드 대조 완료 / 자동 수정·PR·배포 미검증** · 2026-11-14

## 1. 재현 조건과 관측 사실

- 격리된 `sre-lab`의 레드 설정: `SECUREKIT_SERVER_PRICE_ENABLED=false`.
- 가짜 회원 Alice가 상품 202를 **가격 필드 없이** 장바구니에 담은 뒤 주문했다.
- `measurements/stages-red-20261114T003106Z.json`의 `error_order_without_price`는 HTTP **500**, 본문 code **500**, 추적 ID `sre-dceda9f6265c4f43`이다.
- 같은 추적 ID를 Loki에서 조회하면 `OPS error.unhandled`의 `reason=NullPointerException`, `target=handler:OmsPortalOrderController.generateOrder`와 예외 처리 로그가 나온다. `measurements/log-evidence-20261114.json`의 레드 주문 기록에도 이벤트 1건·NPE 줄 1개·SQL 오류 줄 0개가 있다.
- 홈과 Alice의 본인 주문 조회는 레드에서도 HTTP 200 / 본문 200이었다. 이 사건이 모든 API의 중단이라는 근거는 없다.

## 2. 코드로 좁힌 원인 경로

1. `OmsCartItemController.add()`는 레드 스위치가 꺼져 있으면 `addUnchecked()`로 간다. 가격을 보내지 않은 요청은 이 경로에 가격을 제공하지 않는다.
2. `OmsCartItemServiceImpl.fillFromSku()`는 `server-price`가 꺼져 있으면 SKU 가격을 장바구니 줄에 넣지 않는다.
3. `OmsPromotionServiceImpl.serverPrice()` 역시 같은 스위치가 꺼져 있으면 가격을 보완하지 않는다.
4. `OmsPortalOrderServiceImpl.calculate()`의 `cartPromotionItem.getPrice().multiply(...)`는 가격이 `null`이면 예외를 낼 수 있다(현재 소스 약 904행).

**결론 수준:** 가격 누락이 서버 가격 보완을 거치지 못해 주문 금액 계산에 들어간다는 설명은 재현 결과와 코드 경로에 맞는다. 저장된 Loki 줄에는 전체 Java 스택 프레임이 없어 예외 발생 **정확한 행**을 로그만으로 확정할 수 없다. 이 행 번호는 코드 대조로 좁힌 후보이며, 실패 테스트 또는 디버거로 최종 확인한다.

## 4. 수정 전후와 남은 검증

`measurements/stages-green-20261114T003602Z.json`의 같은 종류 요청은 HTTP 200 / 본문 200이고 시험 주문 취소도 성공했다. 이 그린 결과는 **랩 스위치를 켠 단건 재연**이며, AI 코드 수정·GitHub PR·Actions 배포의 결과가 아니다.

강의의 실제 수정 단계에서 필요한 증거: 가격 없는 주문의 실패 테스트, 서버 SKU 가격을 쓰는 최소 코드 diff, 정상·할인 주문 회귀 시험, PR·CI, 같은 입력의 배포 후 재시험, 15분 관찰 기록. 승인 전에는 쓰기 작업이 0건이어야 한다.

## 5. 에이전트 평가에 쓸 정답 경계

- **말해도 됨:** 가격 없는 요청이 HTTP 500을 냈다. NPE 이벤트가 있다. 레드 코드가 SKU 가격 보완을 건너뛴다. 그린 스위치 상태에서는 같은 종류 요청이 성공했다.
- **근거 없이 말하면 안 됨:** 정확한 Java 스택 프레임의 행 번호, 전 고객 영향 범위, 운영 서비스의 장애 시간, PR/배포 완료, 취약점 악용 여부.
